# Interface et UX

## Principe

Le monde doit être immersif.

Les panneaux pédagogiques doivent être sobres.

Il faut distinguer :

- information de jeu ;
- information pédagogique ;
- décoration.

## Écran d'accueil

### Hiérarchie

1. identité de Blocland ;
2. environnement / village ;
3. prochaine action ;
4. progression ;
5. accès aux domaines pédagogiques.

### Proposition de texte

# BLOCLAND

## Le savoir construit ton monde.

Explore les îles, relève les défis et reconstruis l'archipel.

**[ Reprendre l'aventure ]**

### Expéditions

**Maths**
Mécanismes & énigmes

**Français**
Archives & récits

**English**
Cartes & messages

### Ton village

En reconstruction

## Écran de carte

La carte doit montrer :

- îles découvertes ;
- îles en cours ;
- îles verrouillées ;
- position du joueur ;
- prochaine destination ;
- progression globale.

Éviter d'afficher trop de statistiques simultanément.

## Écran de mission

### Structure

```text
[ Contexte très court ]

[ Consigne principale ]

[ Zone d'exercice ]

[ Aide audio ] [ Indice ]

[ Valider ]
```

Le décor peut rester visible, mais il ne doit pas concurrencer la consigne.

## Feedback de réussite

Le feedback devrait idéalement relier l'exercice au monde.

Exemple :

> Mission réussie.
>
> Le pont est réparé.

Puis montrer la transformation.

## Feedback d'erreur

Éviter :

- sons agressifs ;
- gros X rouges ;
- perte de points ;
- écran de défaite.

Préférer :

> Pas encore. Regarde cet indice.

## Navigation

Chaque destination importante doit avoir :

- une icône ;
- un libellé textuel ;
- un état visuel ;
- un retour clair.

Ne jamais faire reposer la navigation uniquement sur des symboles ou des couleurs.

## Typographie

Utiliser une typographie lisible et cohérente avec les besoins d'accessibilité.

Conserver Luciole lorsque cela correspond au contexte pédagogique.

## Contraste

Les textes doivent rester lisibles indépendamment du décor.

Prévoir des surfaces ou panneaux suffisamment opaques derrière les informations importantes.
